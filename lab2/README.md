# Запуск
В качестве пакетного менеджера использовалась Conda, venv может быть получен командой
```bash
conda env create --file conda_env.yml
```
venv уже содержит необходимые для запуска ноутбука зависимости (включая Jupyter), сам ноутубк использует относительные пути (сохраняя структуру репозитория) и фиксированные сиды, поэтому результаты должны быть воспроизводимы

# Выводы
**Подход**: приводим все фичи к временной сетке таргета за счёт:
- 0-11 120-минутные окна, т.к. измерения с интервалом 1 минута
- 12-15 используем последнее доступное измеренение (т.е. лаг 1 час) для сохранения каузальности

В результате описанного подхода получается 12\*3 (12 фичей, 3 окна) + 4\*2 (4 фичи, сам сэмпл + дельта по времени) = 44 фичи, дальше понижаетя размерность пространства фичей за счёт PCA (15 коспонент), к ним добавляется таргет с лагом в 1 сэмпл (прошлое лабораторное имерение)

В качестве моделей выбраны:
- Градиентный бустинг
- Случайный лес
- Линенйня регресия с L2 регуляризацией

Нейросетевые методы не подоёдут из-за маленьких размеров таргетов (риск переобучения), SARIMAX не подойдёт из-за того, как были построены фичи (нелинейности + возможны корреляции)

Полученные модели являются статистически адекватными, что подтверждается тестовой выборкой (как метрики, так и визульный анализ), а также анализом остатков. Однако при этом остаток остатков раскрыл определённые недостатки моделей:
- Несмотря на построенные фичи, таргет на лаге 1 оказался куда более значимым
- SHAP и слабая автокорреляция остатков указывают на то, что выбор 15 главных компонент было не самым правильным решением, т.к. не учитывалось влияние на таргет, соответственно это привело к некотрой потере информации

Среди 3 рассмотреных моделей наиболее предчтительной выглядит **линейная регресия**
